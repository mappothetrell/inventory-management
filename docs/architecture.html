Factory Inventory Management System — Architecture

Vue 3 SPA + FastAPI backend, backed entirely by in-memory JSON fixtures. No database.

System Architecture

Browser — Vue 3 SPA
client/ · Vite dev server on :3000 · vue-router, axios, singleton composables (no Vuex/Pinia)
↓
HTTP / JSON via axios — cross-origin, no dev-server proxy
FastAPI application
server/main.py · :8001 · CORS wide open (allow_origins="*") — dev only
↓
Pydantic validation + in-memory list-comprehension filtering
In-memory data layer
server/mock_data.py · module-level Python lists/dicts, loaded once at process start
↓
json.load() at import time — no ORM, no persistence
Static JSON fixtures
server/data/*.json — inventory, orders, demand, backlog, spending, transactions

Data Flow

1
Load
mock_data.py reads every file in server/data/*.json once at process start into module-level Python lists/dicts.
2
Filter
main.py applies apply_filters() / filter_by_month() — plain list comprehensions over warehouse, category, status, order date.
3
Validate & serialize
FastAPI's response_model runs the filtered dicts through Pydantic models before returning JSON.
4
Fetch
client/src/api.js calls http://localhost:8001/api/... with axios, building query params from a filters object (omitting 'all' values).
5
Store
The calling view's loadData() assigns the raw response into a ref() — e.g. allOrders, inventoryItems, summary.
6
Derive
computed() properties re-shape refs into chart/table-ready data reactively — no re-fetch needed for presentational recombination.
7
Render
Templates bind to computed properties for tables, KPI cards, and hand-rolled inline SVG charts.
Filter propagation loop: Time Period, Warehouse, Category, and Order Status live as shared singleton refs in useFilters.js. FilterBar.vue (mounted once, visible on every route) binds directly to them. Each active view's watch() fires on change and re-runs loadData(), restarting the flow from step 2 — only the currently mounted view actually re-fetches.
